# Chunk 4 current implementation choices

## 2026-10-27 — Keep catalog discovery distinct from spectral ingestion

The current development handoff authorizes incremental Chunk 4 work. The first
new implementation is a NASA exact planet-name query/response protocol under
`ecas/ingestion/nasa_discovery.py`, tested offline only. It addresses the missing
target-discovery prerequisite without assuming that catalog parameters are spectra.

This narrow implementation uses the documented pscomppars identity fields and no
scientific measurements. Existing SpectrumData, CSV import, plotting and SQLite
contracts are unchanged. Query building and parsing have no implicit network or
filesystem effects. No new provider registry, dependencies or authentication layer
was needed. Supplied-response parsing explicitly does not authenticate NASA origin.

Historical plan snippets remain reference material. They do not authorize commits,
downloads or credential use, nor certify their own test results. Current field names
and implementation evidence take precedence over misspellings in old snippets.

This does not approve a generic scientific data model, spectral provider selection,
cache identity/schema, alias-resolution policy or molecular-reference conversion.
Those decisions remain open pending source-specific evidence. Full rationale,
verification and next steps are in `Chunk_4_implementation_log.md`.

## 2026-10-27 — Connect the evidenced NASA transmission workflow

Within the continuing Chunk 4 authorization, implement exact-name spectral metadata
search and user-selected transmission retrieval using the existing Qt network
stack. Refresh the workspace from NASA's current interface on each download and
follow the previously inspected source construction; reject a changed layout.
Network operations are asynchronous, anonymous, NASA-host-only, cancellable and
bounded to 15 seconds/1 MiB each. No provider framework or new dependency is needed.

Use a narrow checkout-local sidecar cache, not an implicit change to project SQLite
or SpectrumData. Save original table bytes, exact metadata-response bytes and source
URLs/hashes in a unique entry. Write the manifest last, after format, target and
row-count validation. Reopening verifies hashes and identity again; invalid or
partial entries are excluded. This is a completeness convention, not a claim of
crash-durable transactions or a hostile-filesystem security boundary. Cache listing
and parsing are synchronous local work; total cache-size scalability is unverified.

This resolves the previously open cache choice only for the supported NASA flow.
It does not decide cross-provider identity, aliases, molecular-reference conversion,
full project provenance serialization or scientific compatibility. Existing plan
versions remain unchanged. Argon review remains independent and outstanding.

## 2026-10-27 — Apply batch 2 with exact null semantics

Primary format reference:
https://irsa.ipac.caltech.edu/applications/DDGEN/Doc/ipac_tbl.html . Null markers
must match exactly; case sensitivity is an application policy. Accept mixed-case
supported type declarations by lowercasing type labels, leaving units and original
raw bytes unchanged. Accept a blank numeric cell as None only if the column's
null marker is itself blank. Continue rejecting undeclared blank numeric cells,
and continue rejecting missing wavelength, signal or primary limit flag regardless
of null representation. Empty character fields retain the previous empty-string
behavior when no explicit text marker is supplied. No scientific values are inferred.

Keep evidence format=json exactly as generated by this application. Supporting
externally authored alternate-format URLs is outside the current evidence contract;
the interactive review supplied no failing application path for uppercase format.
Keep URL target-case and parameter-order tolerance, but retain empty parameters
during parsing so blank duplicate/unknown parameters cannot disappear undetected.
Malformed queries/endpoints return False from matching_search_url.
